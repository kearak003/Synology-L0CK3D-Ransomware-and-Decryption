# G．SMB 复制、备份核验与源设备重置

[返回总目录](../README.md)

> 状态：本章是已经选定的后续方案。没有收到 NAS-B 复制完成、完整性核验通过或 NAS-A 已重置的证据，不能把本章写成已完成成果。

## G.1 目标与数据范围

源设备为 NAS-A，目标为另一台群晖 NAS-B。用户选择复制目录 A、B、C、D，以及已由 B 覆盖的入口 B′。物理复制只做四份，避免重复占用空间。

NAS-B 使用独立的新备份共享，不与其原有业务共享合并。源设备系统设置、旧恢复任务和已安装服务不通过系统迁移功能整体搬过去。业务文件仍可能包含安装包和脚本，复制它们不意味着要在目标设备执行它们。

采用 NAS-B 主动通过 SMB 读取 NAS-A 的方式。远程挂载只是访问入口，不是独立备份；最终数据必须真正复制到 NAS-B 的本地存储。

## G.2 准备两个互相分离的位置

在 NAS-B 创建：

| 代称 | 作用 | 是否属于最终备份数据 |
| --- | --- | --- |
| 共享 S | 存放四个远程挂载入口 | 否，内容来自 NAS-A |
| 共享 T | 存放真正复制完成的本地文件 | 是 |

分别在 S 和 T 内准备 A、B、C、D 子目录。实际卷号、共享路径和可用容量必须从 NAS-B 获取，不能假设它与 NAS-A 的布局相同。

容量判断使用待复制文件的逻辑数据量和目标存储能力。源端 Btrfs 的压缩、共享块或稀疏布局不一定通过 SMB 原样保留，NAS-A 的“已用空间”不能直接当作 NAS-B 的容量需求。

## G.3 挂载和复制

在 NAS-B 的 File Station 中使用“工具 → 挂载远程文件夹 → CIFS 共享文件夹”，将 NAS-A 的四个共享分别挂到 S 中对应的空子目录。凭据只在 DSM 中输入，不写入公开脚本、命令行示例或聊天。一次性迁移不需要为了方便而打开长期自动挂载。[群晖远程挂载说明](https://kb.synology.com/en-global/DSM/help/FileStation/mountremotevolume?version=7)

示意映射如下，所有名称均为占位符：

| NAS-A 共享 | NAS-B 的访问入口 | NAS-B 的本地副本 |
| --- | --- | --- |
| A | S/A | T/A |
| B | S/B | T/B |
| C | S/C | T/C |
| D | S/D | T/D |

确认挂载能读取完整范围后，将各挂载入口的内容复制到本地对应目录。选择复制而不是移动。保留后台任务状态、失败列表和冲突处理记录。目标目录使用新的空位置，可减少同名覆盖带来的歧义。

源设备的账号必须能够列出并读取所有需要保存的用户子目录。SMB 可见范围可能受权限和隐藏设置影响，不能只因为目标与“看得见的源”一样就认定源设备全部所选数据已覆盖。受保护子目录、权限错误和非普通对象应单独列出处理决定。[群晖共享文件夹权限说明](https://kb.synology.com/en-af/DSM/help/DSM/AdminCenter/file_share_create?version=7)

## G.4 复制后如何核验

核验应包含三个层次：

1. **覆盖范围**：源端目录、文件和读取失败项有没有明确清单？别名是否去重？应保存的数据是否因权限隐藏而漏掉？
2. **字节内容**：每个需要保留的普通文件在目标中是否存在，大小和完整内容校验是否一致？
3. **可用性**：在 NAS-B 本地打开抽样文档、照片、视频和业务文件。抽查不能替代完整内容核验，但可补充应用层可用性证据。

核验前后都要确认 S 中的入口仍然挂载到正确的 NAS-A 共享，T 则是 NAS-B 本地位置。远程挂载掉线后留下的空文件夹，不能拿来与另一个空目录比较并报告成功。

可以使用 NAS-B 上可用的成熟文件比较工具。例如 rsync 的校验和模式可以避免只依赖大小和时间戳，试运行模式只报告拟议操作。验收需要同时检查退出状态、差异输出、跳过项及错误信息；退出码为 0 并不单独代表没有差异。[rsync 官方手册](https://download.samba.org/pub/rsync/rsync.1.html)

本稿不提供带真实路径的 rsync 命令，也不把删除目标多余文件的选项混进复制任务。待目标路径、挂载和实际权限确认后，应生成只读核验命令并复核其行为。源端和目标端在最终核验窗口应停止新增写入；发生变化的文件重新比较。

SMB 内容复制不自动证明 ACL、扩展属性、硬链接结构、Btrfs 共享关系或应用数据库状态完全保留。必须按业务需求分别验收这些属性，而不能把它们隐藏在一个“校验成功”总标记里。

## G.5 允许进入重置阶段的条件

| 条件 | 所需证据 |
| --- | --- |
| 数据实际位于 NAS-B 本地 | 核对本地路径和挂载关系，解除源挂载后仍可访问备份 |
| 复制任务结束 | 没有正在进行的复制或等待处理的失败项 |
| 内容核验完成 | 无未解释的缺失、内容差异、不可读和覆盖缺口 |
| 抽样文件可用 | 从 NAS-B 本地副本打开并检查 |
| 范围明确 | 用户知道 NAS-A 哪些目录没有复制，并明确不再保留它们 |
| 恢复材料保留 | 必要密钥和私有证据已另行安全保存，或明确决定不再需要 |
| 备份不依赖源端 | 停止会传播删除的同步关系，断开本次远程挂载 |

在源端删除文件可能传递到目标的同步机制，不适合作为“清空源设备前仍持续运行”的唯一备份。群晖共享文件夹同步本身具有源端删除同步到目标的行为，需要与本次独立复制方案区分。[群晖同步说明](https://kb.synology.com/en-global/DSM/help/DSM/AdminCenter/application_backupserv_sharedfoldersync?version=7)

## G.6 重建方案

完成上面的验收后，再在确认过身份的 NAS-A 上执行 DSM 的清除所有数据/出厂重置，并重新安装受支持的 DSM。它会擦除源设备上的用户数据，不等于只重置管理员密码或网络设置。[群晖系统重置说明](https://kb.synology.com/index.php/en-us/DSM/help/DSM/AdminCenter/system_restoredefaults?version=7)

重新建立管理员、更新受支持的软件、撤销旧凭据和不必要的外部访问，按需要逐项安装套件。不要为了省事直接回灌尚未验证的系统配置和自动启动项。随后再把必要业务数据从独立备份恢复到新环境。
