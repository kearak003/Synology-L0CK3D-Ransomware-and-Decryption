# D．并发、续跑与结果验收

本案例经历了多轮从只读盘点、缺失明文优先恢复、并发收尾到固定清单清理的迭代。最终优先范围由 `A`、`B`、`C`、`D` 四个实际目录组成，入口 `B′` 解析后已落在 `B` 内，共计五个入口。恢复入口使用这组目录，固定清单清理入口仅处理名单中的遗留项。进度和收尾证据都要注明作用范围。

## 并发入口、单文件事务和全局限流

最终优先运行给每个实际目录配置 100 个任务工作协程，四个目录合计 400 个调度名额。目录归属在启动时固定，`B′` 不另开一组，卷根文件也没有独立工作通道。扫描生产文件任务，工作协程消费队列。候选处理、逐件清理和后续重新盘点各自有明确的完成点。这样可以让多个目录并行推进，同时减少同一对象被两个入口重复处理的机会。

同时执行昂贵工作的数量，由全局 I/O 名额限制。实际名额使用可用内存和文件描述符硬上限计算，恢复缓冲池也受名额限制。磁盘分配另受每文件预留和卷级余量约束。程序需要时仅在现有硬限制内调整本进程的描述符软上限，并读回确认。全局空间管理同时计入当前事务的数据分配和待写的元数据、队列及日志，避免每个协程都把同一份剩余空间算成自己的。400 是任务可调度上限，实际并行 I/O 可能低得多。介质随机读、全流复读、CoW 放大、元数据同步和正常业务竞争，都会影响每秒处理文件数。

测吞吐时，可记录目录扫描速率、等待 I/O 名额的时长、实际占用峰值、内容校验读入字节、候选写入字节、文件完成速率、同步等待及卷的可用空间。可同时观察小文件与大文件队列，避免用少数大文件的逻辑字节变化推断所有工作都顺利。比较批次要保持根范围、文件类型和验证要求一致。日志中的计划工作数、活跃文件数、真正完成的文件数应各列一项。

## 各层锁分别保护什么

- 运行级排他锁保护同一恢复范围的写入权，也防止前任、后任使用各自的日志同时修改数据。续跑须证明旧任务已退出，并持有当前需要的全部锁；实际入口会检查锁对象、描述符身份及活跃的租约。前任状态写“结束”只属于线索。
- 文件级声明及操作系统的咨询锁保护具体对象。读取源或供体时持共享锁，需要替换的旧目标持排他锁。对同目标及其旧事务别名要互斥，对无关文件可以并行。咨询锁只能约束遵守协议的参与者，因此还要检查绑定路径、目录句柄、完整内容和实际引用。
- 全局资源锁保护预留总量和 I/O 许可。占有统计锁时只更新小范围状态。磁盘读取、克隆、计算摘要和写审计在适当粒度下执行。以同一文件事务的互斥保护它自己的关键区间，其余目录与文件继续工作。

可以把候选发现、排序和报告格式化移到短共享锁之外。目录清单、候选角色、稳定的根映射可以作预筛缓存。缓存命中后，发布及删除仍使用当前的目录句柄重新确认设备、inode、链接数、属性、权限与已打开引用。目录枚举的 EOF 也可能过时，不能作为之后清理的最终证据。这里甚至有内容变化无法依靠同一时间粒度内的 `fstat` 区分的情况，关键边界的完整内容读取必须保留。好处是缩短共享锁与等待队列的占用时间，逐文件的删除条件保持充分。

## 目录边界与日志

启动时仅解析预先批准的入口，核对规范路径和实际目录身份。显式批准的 `B′` 可以解析为 `B` 内的入口，发现阶段遇到普通符号链接只登记该链接，遍历到此为止。扫描采用有界待访问队列和分批读目录，按设备和 inode 去重，避免递归处理入口别名、循环或同一目录多次。打开目录后再次绑定挂载与归属，遇到未授权挂载、快照、受保护目录、无法打开的路径或对象身份变化，列出不能证明覆盖的范围。扫描读取失败、队列预算耗尽或并发修改影响目录成员时，不能把未知部分统计为零。过程目录 `T` 进入专门的收尾路径，避免把中间文件当作普通业务数据再次恢复。

日志同步也会成为瓶颈。该案例把全局审计队列的追加与同步确认做成组提交，调用者在要求持久化时必须等到成功确认。仅用于列出剩余勒索信候选的报告另做有界批量写入，每批同时确认私有审计与残留输出，检查点随后才能前进。报告尾部要成功关闭才算完整。发布意图、删除意图、逐文件过程日志、目录同步和清理后的核对仍在各自关键边界完成。这样可以区分“正在把清单写完”和“已经实际删除了多少”，也能避免大批报告行所花的时间被误读为数据恢复卡住。

## 来源检查曾反复阻断任务

早期运行把系统中某类进程的身份读取作为全局准入条件。一次读取能看到进程状态和启动信息，后续读取可执行文件或父链时该进程可能已经退出。历史日志中确实出现过此类身份读不到而停止的情况。已有日志不足以证明那个进程属于哪个服务，也不足以证明它安全或恶意。把采集不全当作永久阻断，引发了重复停机、重做交付包和重新启动，恢复数据本身没有从这些重复步骤受益。

一次身份检查可跨多次系统调用，应把首次观测和真实读取错误保留，并按进程号、启动时间、当前程序与父链区分自然退出、进程号复用、权限读取失败、I/O 异常及已观察到的身份变化。优先收紧会影响写安全的范围。对满足审核条件的短暂观测中断，暂停接纳新的修改，等已进入持久化边界的操作排空，保留受不完整观测影响的事务，再以一轮完整的当前结果恢复准入。真正的身份变化、对象仍有冲突引用或无法证明保护条件时，继续保留并报告。进程消失这个现象单独不足以恢复写入。

最终优先运行采用了单独审核的配置。运行级检查聚焦租约、授权卷和运行目录、空间与审计健康，逐文件仍强制源、目标、引用、inode 和提交边界检查。这与早期持续采用广泛进程来源判定的模式有所不同。遇到另一个陌生受害环境，仍应先确认写入权，避免交给可能与恢复争用的进程，按环境验证隔离和引用判断。

## 自检、部署与续跑

验证应标明在哪一层执行。Windows 本机运行的测试能检验格式判定、调度、资源计算、历史证据规则和其他跨平台逻辑。对 Linux 目标的静态检查、交叉编译和确认测试注册只说明能构建并包含选定入口。Linux 文件锁、Btrfs 克隆与挂载身份、平台权限及掉电相关持久化边界，需要在对应的 Linux 文件系统中验证。Windows 的实际文件恢复入口会拒绝执行这些 Linux/Btrfs 写入流程。

实际设备上的发布自检使用本轮新建并验证归属的隔离测试目录，以合成样本覆盖克隆、缺失与已存在的同名目标、别名、挂载检查、只读核验、旧过程目录和审计写入。需测试文件被替换、内容变化、同步或关闭失败、空间或描述符紧张、控制路径停止及中途取消等反例，确认遗留对象仍可核对。案例的本地验证记录显示 28 个 Windows 顶层测试通过，Linux 静态检查、交叉编译及 33 项设备侧用例的注册检查通过。同一优先交付的真实设备启动日志另有 33 项隔离自检通过记录。这是两份不同的证据，后者仍只覆盖自检用到的样本和行为。

续跑先看当前对象和持久化事务记录，再看上一轮的进度。如仍有受控的旧运行，先等待它退出并排除并行写者。处理优雅停止时，阻止新任务进入提交，给已进入边界的工作时间完成同步，关闭句柄并释放锁。强杀、掉电或系统崩溃后的对象和日志可能停在不同阶段，下一次应只读核对仍存的旧件、过程目录、已发布目标和原始密文。若某个旧过程目录影响一条路径，优先隔离该路径，让符合授权及全局保护条件的无关文件继续推进。

## 如何验收最终收尾

1. **先等恢复工作协程结束。** 用新盘点核对已授权目录内可见的密文候选、过程目录、无法确认的条目、无法扫描的范围及错误。进度生成时可能有事务尚在提交，空队列或退出成功不足以确认整个范围。
2. **再核对独立残留项。** 勒索信的新一轮盘点完整、扫描无错误且授权范围检查通过后，可以逐一清理已独立确认且指纹匹配的 `N`。未决过程目录和符号链接继续保留，选定范围的总体状态仍为不完整。名称相似但未确认的文件留待检查。过程目录 `T` 要辨别空目录、仅存事务日志、独有载荷和已证明重复的载荷。符号链接仅在固定清单授权且对象身份复验通过时解除链接。判断链接对象始终用不跟随链接的检查，删除不沿链接指向的位置展开。
3. **核对清理后状态并分开记录结论。** 最终优先范围的重新盘点观测到密文候选为 0。随后只读核验与固定清单清理覆盖 35 个遗留过程目录、327 个符号链接与 2 个后来核实的勒索信文件，合计 364 项。清理结果逐项复核，报告显示固定清单内 364 项全部已不存在、未决项为 0。前一次盘点与后一次固定清单是不同口径，不能把固定清单的数字当成全卷扫描数。
4. **说明尚未验证的范围。** 以上是用户选定范围内、当时可见且已识别的密文候选和固定清单的状态。其他目录、快照、曾丢失或被覆盖的历史文件、平台属性是否完整以及系统上是否仍有入侵痕迹，需要各自的证据。数据恢复报告不能判断整台设备是否已清除恶意程序。
