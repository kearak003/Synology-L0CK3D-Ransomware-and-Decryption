# I．脱敏规则与公开发布边界

[返回总目录](../README.md)

## I.1 公开包包含什么

公开包仅包含这套 Markdown 技术文档和一个限制新增文件范围的忽略配置。脚本目录是能力与版本索引，不是可直接运行的程序发布。

原始源码包含本案例的设备和历史证据绑定。把这些值简单替换为占位符，程序可能直接失效，也可能改变原本依赖的安全条件。因此本次只公开用途、数据流、关键检查和验证结果，不把“脱敏后的破坏性脚本”包装成通用工具。

## I.2 字段处理规则

| 信息 | 公开处理 |
| --- | --- |
| 管理地址、内网地址、主机名、设备标识 | NAS-A、NAS-B 或明确占位符 |
| 用户名、用户主目录、个人文件名 | 字母别名或业务类别描述 |
| 实际共享目录与文件路径 | 目录 A/B/C/D、入口 B′、示意路径 `/VOL/A/a` |
| 勒索信和过程文件的真实名字 | 文件 N、过程目录 T；不提供可复制的通用匹配规则 |
| 密钥、口令、Cookie、令牌、内存转储 | 完全排除，不保留片段或可逆编码 |
| 运行编号、进程号、设备序列、inode 清单 | 移除具体值，只解释字段用途 |
| 文件内容和实际摘要 | 不公开；只解释摘要如何参与校验 |
| 脚本真实名称、部署路径、任务原名称 | 用公开脚本编号和角色说明 |
| 截图、浏览器导出页、原始 ZIP 日志 | 不进入公开包 |
| 版本演进、错误类别、汇总数量 | 在不包含身份关联数据的前提下保留 |
| 标准 API、产品名和官方资料链接 | 保留技术名称，便于读者查证 |

公开文件自己的名称，例如本文档入口和章节文件名，是新建的导航名称，不对应原始 NAS 数据。

## I.3 私有映射如何保存

为保证整理过程可核查，本地另存“公开别名 → 原始材料位置”的映射及证据索引。该映射位于公开目录之外，不能与文档一起上传。原始摘要即使不是密码，也可能与其他数据集关联，因此只保存在私有核对记录中。

文档的脚本统计按可确认的本地材料生成；内容相同的副本合并，核心模块和测试组按职责说明。缺少实际执行证据的程序标记为准备、候选或验证边界不明，不能用文件存在来推断部署成功。

## I.4 发布前检查

1. 检查公开包内只有预期的 Markdown 文件和忽略配置。
2. 搜索网络地址、个人路径、真实用户与共享名、原始运行编号、实际摘要和密钥片段。
3. 检查 Markdown 链接：本地链接只指向公开包内文件，不连接到私有原始日志或源码。
4. 检查代码块和 Mermaid，确保它们使用占位路径，没有真实操作目标。
5. 检查事实措辞：计划、已写代码、本地测试、NAS 自检和真实完成必须分开。
6. 检查压缩包成员，不要因选中了父目录而把私有材料一起打包。
7. 上传到新的仓库工作目录或干净的公开分支；不要把原始工作区的提交历史推送到公开仓库。

正则检查和敏感词检查不能证明绝对没有隐私风险。文件名、路径和强标识的自动检查之外，还要人工查看叙事是否包含可识别的个人或组织背景。

## I.5 GitHub 上传方式

这套文档可放在新仓库根目录，保留入口文档与章节目录的相对关系。可先在本地或私有草稿中预览，再将同一份经过核对的文件发布到目标公开仓库。

本次没有创建仓库、推送提交或公开上传材料。仓库名称、所有者、许可协议及文档作者展示方式由发布者决定。本包没有替发布者设置真实姓名、邮箱或第三方代码许可。

若后续需要开源实际程序，应当作为独立工程处理：去除设备硬编码和私有样本，重新建立通用配置与权限边界，验证真实文件系统行为，补充支持矩阵和许可证，并单独接受安全审查。
