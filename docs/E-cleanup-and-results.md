# E．收尾清理、未决项与最终结果

[返回总目录](../README.md)

## E.1 清理为什么要成为独立阶段

恢复过程会留下工作目录、候选文件、旧副本、事务日志和锁。它们可能是正常中间状态，也可能是任务中断后唯一能够判断提交状态的材料。只按名字删除所有“看上去临时”的文件，会破坏续接依据，甚至删掉唯一可用副本。

独立清理程序还必须与恢复程序协调。两个不同的 DSM 任务可以有独立日志和调度，但如果它们操作同一批文件，就不具备相互独立的破坏权限。本案通过协调锁和恢复租约保证清理开始前不与旧恢复事务同时修改相同对象。

## E.2 第一轮收尾的可确认结果

一次正常结束的并行收尾运行耗时约 87 分钟，报告显示：

| 项目 | 数量或状态 |
| --- | --- |
| 已删除的已确认勒索信 | 72,356 |
| 已清理的过程目录 | 387 |
| 所扫描范围内剩余已识别密文 | 0 |
| 剩余已识别的标准名称勒索信 | 0 |
| 保留的过程目录 | 35 |
| 相似名称但尚待确定的文件 | 2 |

| 受保护边界 | 1 个子目录 |
| 扫描错误 | 0 |

这一轮没有新增解密成功数；它的实际工作主要是收尾。不能把删除勒索信的数量写成新恢复文件数。

当时“尚未完全干净”的标记是合理的。正常退出表示程序完成了它的一轮处理，保留项则表示范围内仍有需要另行判断的对象，二者不矛盾。

## E.3 35 个过程目录为什么没有自动删除

初始清理只知道：34 个过程目录内的候选内容与现存目标不同，缺少足以直接确认可以丢弃候选的事务凭证；另有 1 个目录当时为空，但权限是 0711，而旧规则要求 0700。

随后进行定向只读核验。它固定读取这 35 项的身份、有限长度的事务记录和现存副本完整摘要；仅对链接读取其自身元信息，不跟随目标。它没有解密、覆盖或删除数据。

核验后的事实是：

| 类型 | 数量 | 正确解读 |
| --- | --- | --- |
| 候选文件为空，现存目标仍在 | 32 | “摘要不同”并不等于存在第二份完整有用原文；这些是未完成的空候选 |
| 候选非空、与现存目标内容不同 | 2 | 合计约 769 MiB；两份都是安装介质类型，不能仅凭大小相同判断哪份正确 |
| 空过程目录、权限不匹配 | 1 | 原规则保守留下；空目录状态和身份需要重新确认 |

公开稿不提供这两份非空候选对应的真实名称或摘要。现存文件被保留；本轮也没有证明它们一定等于攻击前的历史原文。

## E.4 相似名称文件的处理

标准名称匹配之外还发现了 2 个文件。只读核验发现它们的内容与已经确认的勒索信指纹一致。它们位于回收相关范围，其中一项位于元数据子目录；报告不能证明由哪个服务生成或改名。这说明仅匹配一个固定名称可能漏掉内容相同的名称变体。

安全规则是“候选名称用于发现，已确认内容用于判断”。同名正常文档不能因为名称相似就删除；未知内容需要列入未决项。

## E.5 327 个符号链接不应被描述成恶意文件

“扫描未跟随符号链接”是一项范围说明，不是恶意判定，也不证明链接已损坏。链接可能用于索引、缩略图、应用包结构或普通文件别名。

本案最终删除这些链接，是用户对固定清单作出的明确选择。删除动作只作用于链接自身，不访问或删除其目标。此操作可能改变依赖这些链接的目录结构或应用行为，不能推广为“遇到符号链接就删除”的恢复规则。

## E.6 最终固定清单的授权与实施

用户明确授权删除固定清单中的 35 个过程目录及其内容、327 个符号链接自身，其中包括两份非空替换副本。之前的清理授权也覆盖已确认的勒索信，因此将 2 个新确认文件纳入同一轮。

清理方案采用固定清单，而不是按名称重新搜索后无限扩大删除范围：

1. 将只读报告绑定到程序的授权清单，校验清单内容和程序版本。
2. 取得协调锁与恢复租约；锁占用时退出并报告，不删除锁来强行运行。
3. 固定共享根和父目录链，拒绝符号链接替换、挂载边界变化或陌生路径。
4. 对过程目录核对身份和当前子项；只允许清单中的事务文件和候选文件，出现额外内容则保留该项。
5. 对仍存在的子文件核对完整摘要，再删除各自明确授权的名称。
6. 对对应的现存目标做身份与属性检查，保持它们原样。
7. 仅在过程目录为空后使用空目录删除操作；不采用递归强删。
8. 对链接核对其自身身份后解除链接，对勒索信重新核对原始摘要和规范化内容指纹。
9. 每项完成即记录；最后重新检查清单中所有路径。

两份非空且内容不同的候选也被纳入删除。这是本案用户明确接受的取舍，而不是由“与目标不同”自动推出的安全结论。正常的自动恢复流程不能照搬这个例外。

## E.7 部分完成后的续接

如果一个过程目录的候选已经删除而事务文件尚在，再次执行时，只核对仍存在的固定子项。目录大小和修改时间会因前一次合法删除而变化，因此不能继续机械套用删除前的完整目录时间戳；但目录身份、类型、权限及剩余文件身份仍须符合范围绑定。

已不存在的清单项目记录为“已不存在”，不凭空重建。不识别的新增文件、身份变化或读取错误会保留并报告。这样既支持续接，也不把“重复执行”变成无限扩大的清理动作。

## E.8 最终证据

最终报告及逐项执行日志与授权清单完全一致：

| 清单类型 | 本轮完成 | 最终仍存在 | 需复核 |
| --- | ---: | ---: | ---: |
| 过程目录及已授权内部文件 | 35 | 0 | 0 |
| 符号链接自身 | 327 | 0 | 0 |
| 已确认勒索信 | 2 | 0 | 0 |
| 清单项目合计 | 364 | 0 | 0 |

364 是清单顶层项目数，不能再把目录内部文件重复相加后声称删除了更多清单项。前后两轮中，已列入这组收尾范围的过程目录合计清理 422 个，已确认勒索信合计删除 72,358 条。

清理程序按不同共享目录并发、每个共享最多 100 个工作者组织任务，并根据文件描述符额度约束实际活动数。逻辑大小不等于实际回收空间，因此文档不把约 769 MiB 的候选逻辑大小直接写成已释放的物理容量。

## E.9 仍然存在的边界

一个受保护子目录在此前扫描中未递归进入，最终固定清理没有改变这一边界。历史未跟随链接的目标也没有因此获得内容核验。其他共享目录、快照、系统组件及全盘恶意程序检测不属于这次最终清单证明的范围。

因此本阶段的正确结论是“固定收尾清单完成”。下一阶段是独立设备备份、覆盖范围确认、内容核验和源设备重建，详见[迁移与重置方案](G-migration-and-reset.md)。
