# A．背景、目标与证据边界

[返回总目录](../README.md)

## A.1 这次事件要解决什么

源设备 NAS-A 中的大量文件受到加密，部分正常文件名对应的应用数据已经无法使用。恢复所需的密钥材料在本次工作开始时已经可用。用户最初优先考虑应用和套件数据，随后把重点转到便于迁移的个人与业务文件。

早期恢复过程中，原本约 2 TB 的额外空闲空间持续下降。用户希望采用“恢复一个、校验一个、删除一个”的方式，而不是同时保留一整套额外明文。后来又提出逐步提高并发、加快收尾、列出无法确认的项目，以及把关键数据复制到 NAS-B 后重建 NAS-A。

这些要求包含不同问题：

| 问题 | 需要回答的内容 |
| --- | --- |
| 解密 | 密钥和文件格式是否匹配？哪些字节被加密？输出是否可信？ |
| 空间 | 文件的逻辑大小、物理分配和共享块分别是多少？删除后仍由谁引用？ |
| 属性 | 所有者、权限、ACL、扩展属性和存储标志能否保持？ |
| 在线状态 | 是否有应用、旧恢复任务或后台服务正在修改这些对象？ |
| 并发 | 是 CPU、读取、随机 I/O、锁、属性查询，还是日志落盘在限制吞吐？ |
| 收尾 | 过程目录内是无用空文件、可重建副本，还是唯一有价值的数据？ |
| 迁移 | 复制是否覆盖全部所选数据？内容是否一致？目标是否独立于源设备？ |
| 系统安全 | 恶意驻留和被盗凭据是否已处理？系统是否已可信重建？ |

不能把解密函数能运行，直接等同于上表所有问题均已解决。

## A.2 用户约束如何变化

开始阶段要求尽量恢复原有内容和属性，并尽量利用共享数据块控制新增空间。后续用户明确提高了内容恢复的优先级：属性尽力保留，无法完全一致时应记录差异，避免属性问题阻塞本来可以恢复的内容。

并发策略也经历多次变化：最初少量文件工作者，后来提高到 8 个，再引入多个顶层目录并发；每目录工作者随后提高到 24、64、80 和 100 等配置。并发数变化是调度策略变化，不能据此推断每轮处理了多少文件或获得了多少提速。

最终优先保障的是四个物理共享目录 A、B、C、D，以及重复入口 B′。B′ 的数据已包含在 B 的实际范围中，因此复制时只需四份物理数据集。

## A.3 本文如何区分事实与推断

| 证据等级 | 本文中的用法 | 不能据此推出的结论 |
| --- | --- | --- |
| 用户授权或要求 | 确定处理范围、并发要求、内容优先策略及明确删除意图 | 不能证明动作已经发生 |
| 代码与本地测试 | 说明程序实现的机制、反例覆盖和构建状态 | 不能证明在 NAS 上运行成功 |
| NAS 合成自检 | 证明当次系统上受控假数据的特定能力 | 不能证明所有真实文件都兼容 |
| 真实样本或固定批次 | 证明那些指定对象的事务结果 | 不能推广成整台设备恢复成功 |
| 完整运行报告及对应日志 | 说明该运行的完成数量、残留和退出状态 | 不等于当前在线实时状态 |
| 固定清单最终复核 | 证明指定路径在检查时已不存在 | 不证明全盘没有其他密文、恶意程序或遗漏目录 |

文档依据本地代码、交付说明、验证记录和用户下载的运行报告整理。原始资料属于私有证据，公开包不会附上。因此读者可以复核技术方法和公开资料，但无法通过本仓库独立重放本案全部原始审计。

## A.4 初期保全原则

已掌握密钥不意味着可以立即重启、杀掉所有可疑进程或删除所有密文。需要先确定密钥材料已以可验证、可持续使用的方式保留，识别必要进程和恢复控制程序，并保留未完成事务的现场。

如果需要暂停进程，应核对其真实身份和启动代次，不能按名称或过时的进程编号批量操作。进程处于不可中断 I/O 状态，也不能被当作已经成功冻结。对线上服务的限制应结合恢复范围和业务状态实施，避免在正在写入的数据库上做文件级替换。

本案早期有浏览器内的 DSM 操作和人工密码验证，后期改为“本地准备程序，用户上传、运行任务、下载日志”。后者使部署动作和证据回传更明确，也避免在浏览器连接中断后猜测任务到底是否保存或启动。

微软的事件响应资料强调范围确认、遏制和调查，而不仅仅是运行解密器。本文把这些原则与具体恢复事务分开记录。[微软事件响应资料](https://learn.microsoft.com/en-us/security/ransomware/incident-response-playbook-dart-ransomware-approach)

## A.5 本文不声称什么

- 不声称存在适用于所有受害者的通用密钥。
- 不声称扫描中识别到的加密后缀归零，就证明每个文件内容正确。
- 不声称相同大小、文件可以打开、完整摘要一致或加解密往返，各自都能单独证明历史原文正确。
- 不声称删除勒索信就是清除了勒索程序。
- 不声称全部目录、快照、受保护范围和符号链接目标均已审计。
- 不声称 NAS-B 已完成复制，或 NAS-A 已重置。

这些边界决定了后续还有独立的备份核验与系统重建阶段。
